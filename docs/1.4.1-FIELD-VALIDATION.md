# QSM 1.4.1.0 field-test candidate

Superseded by [1.4.1.1 cloud validation](1.4.1.1-FIELD-VALIDATION.md). Results below describe the earlier candidate.

Validation date: 2026-09-14. This candidate has not been installed for live acquisition or published as a stable release. The current release remains 1.4.0.2.

## Dataset and replay

241 LIGHT frames from one Cocoon Nebula session, 13–14 September 2026: ASI2600MC Pro, RGGB, 6248 × 4176, 3.76 µm pixels, 800 mm focal length, QUAD filter, 120 seconds, gain 100. FLATs are excluded. Private FITS files and the session log are not included in this repository.

The replay calls the same stellar pipeline as the live save callback. It preserves recorded exposure guide aggregates (RMS, peak and longest sustained excursion) and image metrics, processes frames in acquisition order, rebuilds rolling baselines using the candidate's final decisions, and admits only past eligible references. It reads owned raw samples; original science files, names and timestamps remain unchanged. The original log predates the final 1.4.0.2 release; this is a comparison with that recorded session, not a claimed head-to-head live test of two released DLLs.

Recovered original rejects: 0859, 0911, 0967, 1025 and 1042. New rejects: 0856 (confirmed elongation without a guiding alarm) and 0895 (borderline shape retains a guide flag). All 17 independently reviewed stellar-defect cases and all 20 strong signal-loss cases remain rejected. Frame 0989 has a repeated distant image: about 0.90% of the central peak with 95% sample support. A central-core-only check missed this feature.

Frame 0947 remains rejected. Its matched flux is about 69% of prior clean references; an earlier offline comparison including later frames gave a less severe result. The candidate does not use those future references. Frames 0970 and 1020 remain conservative borderline rejects. Eleven previously accepted frames are now usable warnings because the reliable-measurement fraction is insufficient; they are not represented as verified clean images.

## Regression and integration

- 61 assessment, raw-image, reference, API and safety assertions.
- 43 field assertions covering four strong recovery candidates, all 37 reviewed defect/signal cases, independent shape rejection and distant-image detection.
- Previous-night 13-frame regression: six recoveries and seven retained rejects, including 0565.
- WPF cross-dispatcher checks; dark/light native visual renders and desktop/mobile browser checks.
- Production assembly metadata and source-set verification exclude development harnesses and Synthetic Lab.

The private field command is `QualitySessionMeter.AssessmentCheck --field input.json output --assert-cocoon`. Frame identifiers occur only in the optional test oracle, never in production decisions. The original independent review and candidate replay remain separate artifacts.

## Cost and limits

On the development Windows workstation, the 241-frame run measured 9.8 ms median, 48.6 ms p95 and 99.9 ms maximum for analysis, matching and proof generation. Raw capture is separate. Owned samples for this camera total 6.25 MiB per frame; only catalogs and small proof images persist. The extended check ran on 68 frames. These are replay measurements, not performance measurements on the acquisition PC or OpenAstro host.

The evidence covers one camera, filter and optical setup. Gaussian core fitting changes the estimator and needs further field validation on different sampling, optics and star density. Inconclusive images retain existing rejection flags. Extended search is bounded; unknown angular scale or a peak outside the searched field cannot justify severe-guide recovery. Photometry has no independent flux rejection switch and does not measure total exposure value or calibrated transparency. No recovery waits are inserted.

## Delivery and rollback

1.4.1.0 is a candidate package. Close N.I.N.A. before replacing a plugin DLL and keep the prior package and profile backup. The new settings do not reset existing user limits. To roll back, close N.I.N.A. and restore the previous DLL. Replays do not modify historical files. Catalog publication and live acquisition remain separate from this validation.
